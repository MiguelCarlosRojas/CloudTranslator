Especificaciones de Arquitectura y Rendimiento

Detalles técnicos sobre el funcionamiento del microservicio en producción.

[ 01 // SINGLE_REQUEST ]

Una Sola Petición HTTP

El cliente extrae los nodos de texto únicos del DOM y los envía juntos en un único arreglo texts: [...] hacia /api/translate, evitando múltiples llamadas dispersas en el navegador.

[ 02 // COOKIE_PERSISTENCE ]

Persistencia por Cookies

Al seleccionar un idioma, se registra la cookie técnica cloud_translator_lang. Al recargar la página, el cliente lee la cookie y aplica la traducción inmediatamente desde memoria local en 0 milisegundos.

[ 03 // SCHEMA_VALIDATION ]

Validación Estricta con Joi

Cada consulta entrante es verificada por el middleware de validación con Joi. Se controlan los límites de longitud (hasta 1000 textos por lote) y la validez de los códigos de idioma.

[ 04 // TARGET_LANGUAGES ]

Idiomas Oficiales Soportados

Soporte configurado para en (Inglés), es (Español), fr (Francés), de (Alemán), it (Italiano) y pt (Portugués) a través de Google Translate API.

[ 05 // ASYNC_EVENT_LOOP ]

Cero Bloqueo de Renderizado

El cliente utiliza pausas asíncronas para ceder el ciclo de eventos del navegador. La interfaz no se congela y el usuario puede seguir navegando fluidamente.

[ 06 // CORS_SECURITY ]

Soporte CORS Universal

Configurado con encabezados Access-Control-Allow-Origin: * para admitir llamadas directas desde aplicaciones frontend sin requerir proxies intermediarios.

[ INFRASTRUCTURE // RENDER ]

Comportamiento Operativo en Render

La instancia en la nube opera en la infraestructura gratuita de Render. Tras 15 minutos sin peticiones entrantes, la máquina pasa a estado de suspensión automática.

Arranque en Frío: La primera consulta después de un periodo de inactividad tarda aproximadamente 25 a 35 segundos mientras el servidor inicia. Las peticiones subsecuentes responden con latencia promedio de 200 a 400 milisegundos.

Puedes consultar la disponibilidad actual del servidor en la página de Estado del Servicio.
